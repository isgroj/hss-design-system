Focus States

Every interactive element must have a clearly visible focus indicator. Use the HSS design system focus ring: 2px solid var(--border-focus) with 2px offset.

Interactive Demo — Tab through these elements
/* Standard focus ring — all interactive elements */
:focus-visible {
  outline: 2px solid var(--border-focus);
  outline-offset: 2px;
}

/* Never remove outline without a visible replacement */
:focus:not(:focus-visible) {
  outline: none;
}

Typography & Readability

All text must remain readable at 200% zoom. Use relative units in production. Maximum line length: 80 characters.

ContextMinimum SizeHSS Token
Body text14px (1rem)body-base
Secondary / caption12pxbody-sm
Smallest allowed10pxbody-xs
Interactive labels14pxlabel-md
Mobile body (recommended)16pxbody-lg

Readability Rules

Do

Left-align body text. Use sentence/title case for UI headings. Keep line length under 80 characters. Maintain 1.5x line height on body text. Use relative units (rem, em).

Don't

Full-justify body text. Use ALL CAPS for body text (marketing headlines excepted per brand guidelines). Use fixed px for production font sizes. Require horizontal scroll at 320px width.

Semantic Structure

Every page must include proper ARIA landmarks and a logical heading hierarchy. Never skip heading levels.

Required Page Landmarks

<header role="banner">        <!-- App/site header -->
<nav role="navigation">        <!-- Primary navigation -->
<main role="main">             <!-- Primary content area -->
<aside role="complementary">   <!-- Sidebar/supplementary -->
<footer role="contentinfo">    <!-- App/site footer -->

Heading Hierarchy

Page Title <h1> — display-xl
Section Heading <h2> — heading-xl
Subsection <h3> — heading-lg
Detail Heading <h4> — heading-sm
Rules

Exactly one <h1> per page. Never skip levels (no h1 → h3). Dashboard: h1 = page title, h2 = section (KPIs, Charts, Table). Marketing: h1 = hero headline, h2 = section titles.

Forms & Validation

Every form field needs a visible label, descriptive error messages, and proper ARIA attributes. Errors must include text — never color alone.

Accessible Form Pattern
As it appears on your insurance card
Please enter a valid email address (e.g., name@example.com) 
<div class="form-field">
  <label for="email">
    Email address <span aria-hidden="true">*</span>
  </label>
  <input
    id="email"
    type="email"
    aria-required="true"
    aria-invalid="true"
    aria-describedby="email-error"
  />
  <p id="email-error" role="alert">
    Please enter a valid email address.
  </p>
</div>
Do

Display errors inline adjacent to the field. Use aria-describedby to link errors. Move focus to first error on submit failure. Use aria-live="polite" for real-time validation.

Don't

Show errors only at page top. Use only color/border to indicate errors. Auto-dismiss error messages. Use disabled attribute without explaining why.

Alerts & Notifications

Use role="alert" for urgent messages and aria-live="polite" for non-urgent updates. All alerts combine color + icon + text.

Alert Variants (all include icon + text + color)
Error: Unable to save changes. Please try again.
Warning: Session expires in 5 minutes. Save your work.
Success: Your report has been saved successfully.
Info: Your report is being generated. This may take a few minutes.

Motion & Animation

Respect prefers-reduced-motion. No essential information conveyed through animation alone. Keep UI transitions under 400ms.

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
Do

Provide pause/stop for animations >5s. Use aria-busy="true" on loading containers. Keep transitions under 400ms. Disable parallax for reduced-motion users.

Don't

Flash content more than 3 times/second. Convey meaning through animation alone. Use infinite animations without controls. Ignore prefers-reduced-motion.

Implementation Checklist

Use this checklist for every new page or component before shipping.

  • All interactive elements keyboard-accessible
  • Focus indicators visible on all interactive elements
  • Skip link present and functional
  • Heading hierarchy correct (h1 → h2 → h3, no skips)
  • All images have appropriate alt text
  • Color contrast meets minimum ratios
  • Information not conveyed by color alone
  • Form fields have visible labels
  • Error messages are descriptive and linked to fields
  • Touch targets meet 44×44px minimum
  • Page landmarks properly defined
  • Reduced motion preference respected
  • Content readable at 200% zoom
  • Screen reader tested (VoiceOver or NVDA)
  • Language attribute set on <html>
  • Link text is descriptive (no “click here”)
