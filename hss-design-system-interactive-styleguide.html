HSS Design System

Interactive styleguide — Design tokens, components, and marketing brand system

Token Architecture

The HSS design system uses a two-tier token architecture: Primitive tokens define raw values, and Semantic tokens map those primitives to contextual roles. Semantic tokens support Light and Dark modes, enabling automatic theme switching.

Token Flow

Values flow from primitives through semantic aliases to component-level usage. Never reference primitives directly in components — always use the semantic token.

Primitives 82 variables · 1 mode Raw color, spacing, radius values
--color-blue-500 --spacing-16 --radius-md
→
Semantic 79 variables · 2 modes (Light / Dark) Contextual roles that flip per theme
--bg-primary --text-primary --action-primary
→
Components Buttons, Cards, Inputs, Charts... Consume semantic tokens only
btn { bg: var(--action-primary) }

Token Naming Convention

Primitives use --color-{hue}-{shade} and --spacing-{value}. Semantic tokens follow --{category}-{role} where category is one of: bg, text, border, action, success, error, warning, info.

✓ Do

Use semantic tokens in all component styles:
background: var(--bg-primary)
color: var(--text-secondary)
border: 1px solid var(--border-default)

✗ Don't

Reference primitives directly in components:
background: var(--color-white)
color: var(--color-gray-700)
border: 1px solid #e2e8f0

Component Usage Guidelines

When to use each component variant. Follow these patterns for consistency across HSS Data applications.

Buttons
✓ Do

Use Primary for the main CTA (one per view). Use Secondary for supporting actions. Use Ghost for tertiary/in-context actions like table row actions.

✗ Don't

Don't use multiple Primary buttons in the same view. Don't use Destructive for non-destructive actions. Don't disable buttons without explaining why via tooltip.

Cards
✓ Do

Use Data-Stat sm for dense KPI rows. Use md when sparklines add context. Use lg for hero metrics at dashboard top. Always include comparison context (vs. last period).

✗ Don't

Don't mix card sizes in the same row. Don't show more than 6 KPI cards above the fold. Don't omit trend indicators — users need directional context.

Inputs
✓ Do

Validate on blur (not on keystroke). Show error messages below the field. Use hint text for format guidance. Pair date inputs with date picker components.

✗ Don't

Don't validate while the user is still typing. Don't use red borders without an error message. Don't use placeholder text as the only label.

Tabs
✓ Do

Limit to 2–5 tabs. Use short, scannable labels (1–2 words). Keep tab content at the same hierarchy level. Pre-select the most common tab.

✗ Don't

Don't use tabs for sequential steps (use a stepper). Don't nest tabs inside tabs. Don't use more than 5 tabs — consider a sidebar nav or dropdown instead.

Accessibility Guidelines

WCAG 2.1 AA compliance requirements for all HSS Data applications. Contrast ratios, touch targets, focus states, and color-blind safe design patterns.

Contrast Matrix

Key color pairs tested against WCAG AA (4.5:1 normal text, 3:1 large text/UI). Hover to see ratio details.

Touch Targets

Minimum interactive area sizes per WCAG 2.5.8. All clickable elements must meet the 44×44px minimum.

44px
36px
44×44px minimum for all interactive targets. The 36px example fails — add padding to reach 44px. Spacing between adjacent targets must be ≥8px.

Focus States

All interactive elements must show a visible focus indicator. Use the system focus ring — never remove outline without replacement.

Focused Chip

Focus ring: outline: 2px solid var(--action-primary); outline-offset: 2px;

Color-Blind Safe Design

Never rely on color alone to convey meaning. Always pair color with icons, patterns, or text labels.

✓ Do

Pair status colors with icons: ✓ Success, ✗ Error. Use patterns (dashed, dotted) in charts alongside color. Add text labels to legend items.

✗ Don't

Use red/green as the only differentiator. Use adjacent colors from the same hue family. Rely on color alone in data tables for status columns.

Data Visualization Guidelines

Best practices for building effective, accessible charts in the HSS Data platform.

Do

  • Use the dataviz palette in order (1–7) for categorical data
  • Start bar chart axes at zero to avoid misleading comparisons
  • Add tooltips with exact values on all interactive charts
  • Include target/benchmark lines on surgical volume charts
  • Label "lower is better" metrics (readmission, infection, LOS) with directional indicators
  • Show national/regional benchmarks alongside institutional data when available
  • Aggregate patient-level data to cohort level — never display individual PHI in dashboards
  • Ensure 3:1 minimum contrast between adjacent chart segments

Don't

  • Use more than 7 colors in a single chart — aggregate smaller groups
  • Rely solely on color to convey meaning — use patterns or labels
  • Truncate Y-axes in bar charts without clear labeling
  • Use 3D effects, excessive animation, or decorative chart junk
  • Display raw patient identifiers or MRNs in visualizations (HIPAA)
  • Use red/green only for status — include icons or text for color-blind users
  • Show outcome metrics without specifying the time window and cohort definition
  • Compare procedures without risk-adjustment context

Photography

Photography guidelines for all HSS marketing and brand communications.

People on the Move
Photography is used to represent people enjoying their lives and the freedom of movement that we provide to them. Always use color imagery, in clear focus and crop appropriately to display the subject in a flattering way.
Images should always be aspirational.
Families and Community
Images can include people enjoying their everyday lives. Lives that we've enhanced by helping them be their best selves.
HSS in Action
Another area of imagery we use shows our professionals in action, doing what they do best. Avoid overly posed images, and focus on capturing a moment in the lives of our dedicated staff. Ensure that all logos that may appear on clothing or equipment are blurred.
HSS Employee Community
Our HSS family represents who we are as an organization unlike anything else. Showing employees enjoying different aspects of their lives is very important.
Rules: Always use licensed or approved imagery • Never take images from the internet without confirming licensing • Stock photography can be licensed for diverse community representation
